# Architecture & Design Decisions: A5 (Citizen App & Map)

## ADR-A5-001: Visual Identity & Design Token Architecture
- **Context:** Civic-I citizen app requires an editorial, high-trust visual language ("SmartCity Reporter" style) that feels civic, modern, and distinct from generic SaaS dark themes.
- **Decision:**
  - Background: Warm off-white (`#F5F3EE` / `bg-canvas`) paired with dark navy panels (`#1B2536` / `bg-navy`).
  - Accents: Orange (`#E8501F` / `accent-orange`) for primary call-to-actions, blue (`#3B7DD8` / `accent-blue`) for technical/map highlights, gold (`#D4960F` / `accent-gold`) for badges.
  - Geometry: Minimalist square corners (`rounded-none` or `rounded-sm` at 0-2px), crisp 1px borders (`border-navy-light`), and subtle L-bracket corner embellishments (`CornerFrame`).
  - Typography: Space Grotesk for tight, authoritative headings and wide-tracked uppercase labels; serif (Source Serif 4 / Spectral) for readable editorial body text.

## ADR-A5-002: Modular Folder Isolation & Zero-Paid SDK Policy
- **Context:** The citizen-facing application must remain completely decoupled from backend deployments and avoid proprietary or paid cloud SDKs.
- **Decision:**
  - Components partitioned strictly into `build/web/src/shared-ui` (foundational UI widgets), `build/web/src/map` (Leaflet OSM map components), and `build/web/src/citizen` (page wizards and API services).
  - Absolutely zero Firebase, Google Cloud, or Google Maps SDKs used in the citizen interface.
  - OpenStreetMap raster tiles rendered through Leaflet with explicit attribution.

## ADR-A5-003: API Service Layer with Mock Mode Decoupling
- **Context:** Computer vision models (YOLO) and backend endpoints may be actively trained/developed by other team members (M1, M2, A2, A3).
- **Decision:**
  - All network communication isolated inside `build/web/src/citizen/api/reports.ts`.
  - Controlled by `VITE_USE_MOCK=true` fallback flag: produces realistic bounding boxes, category predictions (`pothole`, `garbage` only), confidence metrics, and verification warnings when backend services are offline.
  - Supports multipart upload for submission while client-side validation enforces image constraints before any network dispatch.

## ADR-A5-004: 13-Status Lifecycle Mapping
- **Context:** Complex municipal triage requires transparent tracking from initial report to official verification, inspection scheduling, and resolution.
- **Decision:**
  - Standardized 13 statuses: `SUBMITTED`, `PENDING_ANALYSIS`, `ANALYZED`, `NEEDS_VERIFICATION`, `VERIFIED_BY_OFFICIAL`, `REJECTED`, `SUBMITTED_TO_AUTHORITY`, `ACKNOWLEDGED`, `INSPECTION_SCHEDULED`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`, `REOPENED`.
  - Explicit disclaimer attached to "Submitted to authority": indicates that an official request was formatted and delivered, not that physical field work has commenced.
