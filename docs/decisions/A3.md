# Architecture & Design Decisions: A3 (Ollama Multi-Model Integration)

_Append-only. Each decision requires A1 approval._

## ADR-A3-001: Multi-Model Ollama Integration (extends D8)
- **Status:** PROPOSED — awaiting A1 approval
- **Context:** Decision D8 designated a single Ollama model for inspection-request drafts. The team now has three local models with distinct capabilities: gemma3:latest (vision-capable), qwen3.5:2b (fast text reasoning), and llama3.2:3b (general backup). A multi-model router with graceful fallback increases reliability without adding external dependencies.
- **Decision:**
  - Three model roles: `vision` (gemma3:latest), `decision` (qwen3.5:2b), `fallback` (llama3.2:3b).
  - Text tasks try decision → fallback → deterministic template. Vision tries gemma only; if unavailable, the step is skipped with a warning.
  - New env vars: `OLLAMA_VISION_MODEL` (default gemma3:latest), `OLLAMA_FALLBACK_MODEL` (default llama3.2:3b). Existing `OLLAMA_MODEL` used for decision role.
  - All calls sequential (no concurrency) due to RAM constraints.
  - A shared httpx client with per-role timeouts (30s text, 60s vision) and retries (2 text, 1 vision).
- **Consequences:** Adds ~5 files to services/llm. The deterministic template ensures the pipeline never fails even when Ollama is completely down.

## ADR-A3-002: Advisory Vision Review Step (new, not in MVP scope)
- **Status:** PROPOSED — awaiting A1 approval
- **Context:** The MVP scope includes YOLO classification but no VLM cross-check. Adding an advisory gemma3 vision review can flag YOLO misclassifications and image quality issues for human review, without changing the YOLO result.
- **Decision:**
  - A new optional pipeline step (step 3b) after YOLO, using gemma3 to review the image.
  - Strictly advisory: may only ESCALATE to human review (set `vlm_disagrees`, raise `needs_verification`). Never changes YOLO category/confidence, never lowers `needs_verification`.
  - Images are EXIF-stripped, downscaled to ~768px, sent as base64. No reporter PII or citizen text sent.
  - Prompt forbids statements about depth, structural safety, severity in engineering terms, underground drains, identifying people, or reading plates.
  - When Ollama/gemma is unavailable, a stub reviewer returns "unclear" (labelled STUB) and the pipeline continues.
  - All output marked "AI suggestion, unverified".
- **Consequences:** Adds ~3 files to services/vision. Non-fatal step; pipeline behavior is unchanged if gemma is unavailable.
